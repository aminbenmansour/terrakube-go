Prepare the current change for review. $ARGUMENTS

1. Inspect `git status` and `git diff`.
2. Propose focused conventional commits, split by concern.
3. Write a PR description with Summary, Test plan and compatibility notes.
4. If the change belongs in a stack, say which branch it should be based on.

Do not commit, push or open a PR unless the user explicitly asks.
